# 新游戏接入与导入技术文档

> 目的：**以后再用同一套技术栈做一个新游戏，可以按这份文档直接导入本仓库**，
> 不用重新摸索平台接口，也不用重踩一遍已经踩过的坑。
>
> 面向两类场景：
> 1. **新建游戏** —— 在 `games/` 下从零做一个；
> 2. **导入游戏** —— 游戏已在别处（另一个分支 / 另一个副本）做好，要搬进本仓库并对齐平台能力。
>
> 若只想看"加个游戏最少要做几件事"，读 `games/README.md`；
> 那份是**最小契约**，这份是**完整接口 + 适配清单 + 排错手册**。

---

## 0. 技术栈前提（必须一致，否则不适用本流程）

| 层 | 要求 |
| --- | --- |
| 服务端 | Node 内置模块，**零 npm 依赖** |
| 前端 | 传统 `<script>` + 全局命名空间（`window.WB`），**无打包器、无 npm 前端依赖** |
| 通信 | WebSocket JSON 文本帧 `{ t: '前缀.动作', ... }` |
| 平台层 | `platform/` 只读，**任何情况下都不要改**（游戏靠自动发现挂载） |

平台已在 `platform/web/shared/` 提供：`core.js`（`WB`）、`net.js`（`WB.Net`）、
`friends.js`（好友 + 组队邀请）、`chat.js`（聊天控件）、`app.css` / `friends.css` / `chat.css`。

---

## 1. 导入流程总览

```
① 拷游戏包        games/<名字>/{server,client,shared} → 目标仓库同路径
② 拷自检脚本      tools/<名字>_test.js（有就拷）
③ 改 index.html   补齐本仓库的共享库引用（chat.css / chat.js 很容易漏）
④ 接入平台能力    WB.Chat.boot / enterRoom / leaveRoom、WB.Friends.refreshGame
⑤ 对齐身份适配    持久 key → 刷新能回对局（第 5.6 节）
⑥ 升缓存版本号    index.html 里资源的 ?v=N +1
⑦ 跑自检          node tools/platformtest.js && node tools/<名字>_test.js
⑧ 浏览器验收      建房 → 联机 → 刷新页面仍在对局 → 控制台无报错
⑨ git 提交推送
```

## 2. 服务端接口清单

### 2.1 `new Hub(ctx)` 拿到的 `ctx`

| 成员 | 说明 |
| --- | --- |
| `ctx.send(client, obj)` | 给**一个**连接发消息（`obj` 会被 JSON 序列化） |
| `ctx.clients` | `Map<id, client>`，所有在线连接；`client = { id, name, ip, inviteCode, ... }` |
| `ctx.findByInviteCode(code)` | 按邀请码找连接 |
| `ctx.listOnline()` | 在线列表（好友系统用） |

> 没有广播 API —— 广播要自己遍历房间成员调 `ctx.send`。

### 2.2 Hub 静态契约（平台据此发现并装配）

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `Hub.title` | ✅ | 中文显示名 |
| `Hub.entry` | ✅ | 必须等于 `'/' + 目录名 + '/'` |
| `Hub.routes` | ✅ | `{ '前缀.动作': '方法名' }`，`t` 不在表里的消息**不会被处理** |
| `Hub.order` | 建议 | 主页卡片排序，数字小的在前（默认 100） |
| `Hub.card` | 建议 | `{ desc, tags: [], art: 'card.svg' }` |

### 2.3 生命周期与循环钩子（都是可选）

| 钩子 | 何时被调用 |
| --- | --- |
| `stats()` | 返回值并入 `/api/status`（用于主页/自检） |
| `onClose(client)` | 连接断开 |
| `onRename(client)` | 玩家改昵称 |
| `step(dt)` / `broadcast(dt)` | **只有需要每帧推进的游戏才实现**（如坦克）；回合制不要写 |

### 2.4 消息前缀硬约束

- 一律用**游戏目录名**作前缀：`snake.*`、`ydwg.*`（你画我猜）。
- **平台已占用两个前缀**：`friends.*`（好友系统）、`chat.*`（频道聊天）。
  游戏若占用，平台自检会直接报 `[route conflict]`。

## 3. 前端接口清单（`window.WB`）

| 接口 | 用途 | 备注 |
| --- | --- | --- |
| `new WB.Net()` | WebSocket 客户端 | `.on(type, fn)` / `.send(obj)` / `.connect()`，同源 `/ws`，自动重连 |
| `WB.util.el(tag, cls, htmlOrText)` | 建元素 | 还有 `WB.util.esc()` |
| `WB.ui.toast(msg, type)` | 轻提示 | `type`：`ok` / `err` / `wait` |
| `WB.ui.openSettings()` | 打开设置弹窗 | |
| `WB.bindNetBadge(el, net)` | 把连接状态绑到顶栏徽标 | **每个页面都要调**，否则徽标卡在 HTML 初始文本 |
| `WB.settings` | 昵称 / 音量 / 键位 | 监听 `window.addEventListener('wb:settings', ...)` |
| `WB.audio.play(name)` | WebAudio 现场合成音效 | 无音频文件 |
| `WB.playerName()` | 当前昵称 | **没设昵称时每次连接都会随机生成**，不能当身份用（见 5.6） |
| `WB.Friends.boot(net)` | 挂载好友系统 | 顶栏多出「好友」按钮 |
| `WB.Friends.registerGame({...})` | 登记组队邀请能力 | `name / label / entry / param / canInvite / accept` |
| `WB.Friends.refreshGame()` | 房间状态变了喊一声 | 好友面板的「邀请组队」按钮跟着出现/消失 |
| `WB.Chat.boot(net)` | 挂载左下角聊天控件 | |
| `WB.Chat.enterRoom({game, code, title})` | 进入本局频道 | 频道 id = `game:code`，临时频道，房间没人就回收 |
| `WB.Chat.leaveRoom()` | 退出频道 | 离开房间 / 对局结束时调 |
| `/shared/app.css` | `.btn .panel .topbar .net-badge` 等通用样式 | |

### ⚠️ `net.js` 的一个关键点

连接建立时派发的是 **`'status'` 事件（值为 `'open'`）**，**没有 `'open'` 事件**：

```js
net.on('status', function (s) { if (s === 'open') { /* 连上了 */ } });   // ✅
net.on('open', function () { /* 永远不触发 */ });                        // ❌
```

## 5. 适配项详解（逐条是踩过的坑）

### 5.1 静态资源 URL 必须带 `/<游戏名>/` 前缀 ★最高频

```html
<link rel="stylesheet" href="/drawguess/main.css">   <!-- ❌ -->
<link rel="stylesheet" href="/drawguess/main.css">   <!-- 必须是 /<目录名>/... -->
```

**写错不会 404**：服务端找不到文件会**回退返回 index.html**（HTTP 200 + `text/html`），
浏览器表现为 CSS/JS **静默失效**、**控制台一个错都不报**，只看到"样式没生效"。

排查方法：看响应头

```bash
curl -s -o /dev/null -w "%{content_type}\n" http://127.0.0.1:8080/drawguess/main.css
# 期望 text/css；若是 text/html 就是路径错了
```

### 5.2 `index.html` 的引入顺序（照抄这个顺序）

```html
<!-- CSS：通用 → 好友 → 聊天 → 游戏自己的 -->
<link rel="stylesheet" href="/shared/app.css">
<link rel="stylesheet" href="/shared/friends.css">
<link rel="stylesheet" href="/shared/chat.css">
<link rel="stylesheet" href="/<名字>/<名字>.css?v=N">

<!-- JS：core → net → friends → chat → 游戏自己的 -->
<script src="/shared/core.js"></script>
<script src="/shared/net.js"></script>
<script src="/shared/friends.js"></script>
<script src="/shared/chat.js"></script>
<script src="/<名字>/main.js?v=N"></script>
```

`chat.css / chat.js` 是**本仓库（master）特有的**，从别的分支/副本导入时**最容易漏**；
漏了平台自检会报「页面引入了聊天控件」失败。

### 5.3 游戏内聊天区 与 平台聊天控件 共存

两者**互不冲突**，可以同时存在：

- **平台聊天控件**（左下角）：好友私聊 + 本局频道，走 `chat.*` 消息；
- **游戏自己的聊天区**（页面内）：走游戏自己的前缀（如 `ydwg.chat`），由游戏服务端广播。

游戏自带的聊天区通常要承担**游戏语义**（例如"猜的词要全房可见"），所以两者都保留。
接入时只要在房间生命周期里同步一下平台频道即可：

```js
WB.Chat.boot(net);                                    // 启动时一次
// 建房 / 入房：
WB.Chat.enterRoom({ game: '<名字>', code: code, title: '<中文名> · 房间 ' + code });
// 离开房间 / 对局结束：
WB.Chat.leaveRoom();
```

### 5.4 好友组队邀请

```js
WB.Friends.registerGame({
  name: '<名字>', label: '<中文名>', entry: '/<名字>/', param: 'join',
  canInvite: function () { return state.code ? { data: { code: state.code }, text: '房间 ' + state.code } : null; },
  accept: function (data) { net.send({ t: '<前缀>.join', code: data.code, key: ME_KEY }); }
});
WB.Friends.refreshGame();   // 房间状态变了就喊一声
```

> 好友以 **IP** 为身份单位。`data` 里放房间号这类**当前会话**信息，不要放连接 id。

### 5.5 前端资源缓存版本号

服务端发 `no-cache` 但没有 ETag，浏览器仍可能拿旧文件。
**改完 CSS/JS 如果发现"改了没生效"**，把 `index.html` 里 `?v=` 的数字 +1。

### 5.6 刷新 / 断线要能回到对局（房间制游戏必做）★

玩家按 F5 时，平台会给这条连接一个**新的 id**。如果服务端只认 id，刷新 = 被踢出房间。
要做三件事：

**① 客户端生成持久身份钥匙（每个标签页独立，刷新保留）**

```js
var ID_KEY = '<名字>.id';
function myKey() {
  try {
    var k = sessionStorage.getItem(ID_KEY);          // 用 sessionStorage：每标签页独立
    if (!k) { k = 'k' + Date.now().toString(36) + Math.random().toString(36).slice(2, 8);
               sessionStorage.setItem(ID_KEY, k); }
    return k;
  } catch (e) { return ''; }
}
```

> 不能用 `WB.playerName()` 当身份：用户没设昵称时它**每次连接都随机生成**，刷新后对不上。
> 也不能用 `ip + 昵称`：同理。

**② 服务端：建房 / 加入时记下这把钥匙，重连时按它归位**

```js
// 房间上记 hostKey，成员上记 key
member.key = key || (client.ip + '|' + client.name);

// join()：对局进行中，只要这个身份之前在房间里，就放行并归位
const back = room.members.find((m) => m.key && m.key === backKey);
if (back) {
  const oldId = back.clientId;
  back.clientId = client.id;      // 换成本次连接 id
  back.left = false;              // 从「已退出」恢复
  room.scores[client.id] = room.scores[oldId] || 0;   // 分数跟着搬家
  // hostId / painterId / order / painterPool 里的旧 id 也要换成新 id
  ...
}
```

**注意**：千万别写成"对局中一律拒绝加入"：

```js
if (room.state === 'playing') { this._err(client, '正在进行中…'); return; }   // ❌ 刷新就被踢
```

**③ 服务端：把当前局面补发给回来的人**

光回座位不够 —— 画板/棋盘上的已有内容也得补上，否则他看到的是空盘：

```js
_sendSnapshot(room, client) {
  if (!room.turn || !room.turn.ops.length) return;
  this.ctx.send(client, { t: '<前缀>.opBatch', ops: room.turn.ops.slice() });
}
```

客户端收到后逐条重放；同时提供一条主动拉取的路由（如 `{t:'<前缀>.canvas', op:'sync'}`）更稳妥。

### 5.7 成员"退出"要留档还是清掉

- **大厅里走的人**（还没参与过）：直接从列表移除；
- **对局中 / 结算时走的人**：**留档**（只打 `left: true` 标记），
  这样积分榜和名单里还留着他的成绩，不会突然少一个人；
  同时广播一条 `<前缀>.playerLeft`，其他人弹 toast + 聊天区留痕。

配套：所有玩法判定（人数门槛、轮换顺序、准备状态）都要用 `_active(room)`（过滤掉 `left`），
不能用 `room.members` 直接算。

### 5.8 首页卡片

`client/card.svg`：**600×148 纯 SVG**，不引外部图片、不含脚本。
`Hub.card.art` 写文件名即可（相对自己的入口）。

### 5.9 自检脚本

游戏自检放 `tools/<名字>_test.js`，命名与既有脚本一致。导入后必跑：

```bash
node tools/platformtest.js        # 平台装配契约（含"页面引入了聊天控件"）
node tools/<名字>_test.js         # 游戏自身规则
```

建议在自检里加**源码级回归守卫**，挡住那些自动化测试跑不到的坑，例如：

```js
ok(/var key = [^;]*rgb\.r/.test(padSrc), '笔刷缓存键带上了颜色分量（否则换色无效）', '');
ok(/net\.on\('<前缀>\.chat'/.test(mainSrc), '★ 聊天消息有渲染处理器（否则发出去没人显示）', '');
```

## 7. 排错表（现象 → 原因 → 怎么做）

| 现象 | 常见原因 | 排查 |
| --- | --- | --- |
| CSS/JS 完全没生效，控制台无报错 | 资源路径少了 `/<名字>/` 前缀 | `curl` 看 `content-type`，是 `text/html` 就说明回退到了 index.html |
| 顶栏连接徽标永远「未连接」 | 没调 `WB.bindNetBadge` | 全局搜 `bindNetBadge` |
| `net.on('open')` 不触发 | `net.js` 派发的是 `'status'` | 改成 `net.on('status', s => s==='open' && …)` |
| 聊天发出去就没了 | 客户端漏了对应消息的渲染处理器 | 搜 `net.on('<前缀>.chat'` |
| 房主的「开始游戏」按钮不见了 | ① 按钮用了 `btn primary ghost`（白底白字隐形）<br>② 页面被回收重载后 id 变了、被当成别人 | ① 禁用态别叠 `ghost`<br>② 做 5.6 的身份归位 |
| 改了前端却没生效 | 浏览器缓存 | `?v=` +1 |
| 刷新页面就退出房间 | `join()` 在对局中一律拒绝 | 见 5.6 ② |
| 换颜色但画出来还是旧色 | 笔刷戳子缓存键拼了对象（`[object Object]`） | 键里用 `rgb.r,g,b` |
| 全屏 / 拉窗口后画面变形 | 画布撑满容器，宽高比变了 | 画布按**固定比例**（如 4:3）内缩居中 |
| 两个玩家看到的画面不一样 | 只在本端生效、没走服务端广播；或算法依赖本地尺寸 | 权威判定放服务端；填充这类算法在**固定参考分辨率**上算 |

## 8. 参考实现：你画我猜（`games/drawguess/`）

本次导入的实例，可以照着看每个适配点是怎么落的：

| 关注点 | 落在哪 |
| --- | --- |
| 服务端契约 + 房间/回合/计分 | `server/room.js` |
| 题库（前后端共用） | `shared/words.js` |
| 独立绘画组件（12 种笔刷 / HSV 色环 / 油漆桶 / 图层 / 撤销重做 / 缩放平移） | `client/paintpad.js` + `paintpad.css` |
| 亮色主题（不共用机房主页的深色霓虹，只覆写 CSS 变量） | `client/drawguess.css` |
| 刷新回对局 | `room.js` 的 `join()` 归位分支 + `_sendCanvasSnapshot()`；`main.js` 的 `myKey()` |
| 平台聊天 / 好友适配 | `main.js` 的 `WB.Chat.*` / `WB.Friends.*` 调用 |
| 自检 | `tools/drawguess_test.js`（205 项，含源码级回归守卫） |

**它的聊天区与平台聊天共存的方式**：游戏内聊天区负责"猜的词全房可见 + 猜错 10 秒冷却"
这类游戏语义（`ydwg.chat` / `ydwg.guess`），平台聊天控件负责好友私聊和本局频道（`chat.*`），
两套消息前缀不同、互不影响。
