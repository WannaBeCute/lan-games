# 机房小游戏 · 坦克大战 & 五子棋

可以在机房局域网里直接跑起来的小游戏合集（目前两个：坦克大战、五子棋）。
**服务端零 npm 依赖**（WebSocket 协议用 Node 内置模块自己实现），
任何一台装了 Node.js 的 Win 电脑双击 `start.bat` 即可开服，其他电脑用浏览器打开地址就能玩。

平台层与游戏层是分开的：**想再加一个游戏，只需要在 `games/` 下新建一个文件夹** ——
服务端会自己发现、自己挂载，主页也会自动多出一张卡片，`platform/` 一行都不用改
（约定与模板见 [`games/README.md`](games/README.md)，里面有段可直接发给同学或 AI 的提示词）。

```
双击 start.bat  →  控制台会打印局域网地址（如 http://192.168.1.5:8080）
同学浏览器输入该地址  →  主页选游戏  →  开玩
```

> 想拿源码、或者想一起开发？仓库在 GitHub（公开）。克隆地址、加游戏的步骤、协作流程与自检清单
> 见文末 **8. 获取代码 · 一起开发**。

## 1. 运行环境

| 项目 | 要求 |
| --- | --- |
| 服务器 | 任意一台 Win 电脑，安装 [Node.js](https://nodejs.org)（**建议 18+，最低 14**） |
| 客户端 | Chrome / Edge 等现代浏览器，无需安装任何东西 |
| 网络 | 所有电脑在同一局域网；**不需要外网** |
| 依赖 | **0 个 npm 包**，不需要 `npm install` |

启动方式二选一：

```bat
:: 方式一：双击（推荐，中文名更好找）
启动游戏.bat
:: 或者
start.bat

:: 方式二：命令行
node platform/server/server.cjs                     :: 默认 8080 端口
node platform/server/server.cjs --port 9000
```

> **请勿直接双击 `platform\server\server.js`。** 那个文件不是入口，只是防误点提示；
> 双击 `.js` 会被 Windows 自带的脚本宿主（JScript）打开，弹出 `语法错误 800A03EA`。
> 正确的入口是 `platform\server\server.cjs`。
>
> 首次运行若 Windows 弹出防火墙提示，请选择「允许访问」，否则其他电脑连不上。
> 若是机房统一管理，可让管理员放行该端口，或用 `--port` 换一个已放行的端口。

## 1.1 让别的电脑访问（联机步骤）

**第 1 步 · 在服务器那台电脑上启动**（双击 `启动游戏.bat`）。窗口里会打印出要分享的地址，例如：

```
  【本机打开】  http://localhost:8080

  【让别的电脑访问下面这个地址】
      http://10.10.243.136:8080         (以太网)
```

同时在浏览器打开 `http://localhost:8080`，主页上会出现一条绿色的
**「让别的电脑访问下面这个地址」** 提示条，点「复制地址」就能直接发给同学。

**第 2 步 · 其他电脑**：连上同一个机房网络（同一网段），
用 Chrome / Edge 打开那个地址就行 —— **不需要安装任何东西**。打开后进主页 → 选游戏 → 联机。

**第 3 步 · 在对局里碰头**

| 游戏 | 怎么找到对方 |
| --- | --- |
| 坦克大战 | 房主点「新建房间」，把 **4 位房间号**告诉同学；同学点「加入房间」输入房间号 |
| 五子棋 | 各自页面上的 **邀请码** 给对方，或输入对方的邀请码点「发起邀请」，对方接受即开局 |

### 打不开怎么排查（按顺序）

| 现象 | 原因与处理 |
| --- | --- |
| 同学浏览器显示「无法访问此网站」 | ① 两台电脑是否在同一网段；② 地址是否用了**局域网地址**而不是 `localhost`；③ 见下一行防火墙 |
| 地址没错但仍然连不上 | **Windows 防火墙拦了入站端口**。右键 `开放防火墙端口.bat` → **以管理员身份运行**（换端口就带上参数，如 `开放防火墙端口.bat 9000`）。撤销：`netsh advfirewall firewall delete rule name="机房小游戏 8080"` |
| 服务器窗口被关了 | 服务就停了。窗口需要一直开着，关窗口 / Ctrl+C 即停止服务 |
| 电脑有多个 IP，不知道用哪个 | 以窗口里打印的为准（已自动过滤 VMware / WSL 等虚拟网卡），和主页绿色提示条里的是同一个 |

## 2. 坦克大战

### 2.1 玩法

- 坦克**只用键盘**控制，完全不需要鼠标。坦克可以 **360° 连续旋转**，炮弹沿车头方向飞出：

  | 按键 | 作用 |
  | --- | --- |
  | **↑** | 前进（沿车头方向，可以是任意角度） |
  | **↓** | 后退 |
  | **←** | 左转（逆时针，约 240°/秒） |
  | **→** | 右转（顺时针，约 240°/秒） |
  | 开火键 | 发射，只有一个键 |

- **子弹上限 5 发**：同屏属于你的子弹最多 5 颗，打完再补，必须控制节奏。
- **子弹会撞墙反弹**：打到墙上按入射角反射（竖直面翻 X、水平面翻 Y、犄角原路弹回），
  一枚子弹最多反弹 8 次。
- **子弹飞一段时间会自己消失**：每发子弹存活 **3.4 秒**，到点自动消失，不会一直乱飞。
- **子弹会打中自己**：射出炮口后它就不再认主人了 —— 在墙角开枪很容易被弹回来的子弹打死，
  **贴墙乱开枪是很危险的**。（自己被自己打死会计一次死亡，但不会给任何人加击杀。）
- 地图只是**「看起来像迷宫」**：在空场地上随机画大量走向随机的墙段（途中还会拐弯）+ 随机 2×2 方块，
  形成**多岔路、多死胡同**的曲折布局 —— 每次都不一样，**不是规则迷宫**（没有房间网格那套结构）。
  内部墙体占比稳定在 **24%~36%**（墙面足够多，比早期版本密得多），
  可活动空地仍保证 **≥ 全图 1/3**（实测 52%~62%）。
- **出生点是随机的**：从开阔空地中随机选取，再用「最远点采样」把几辆坦克彼此拉开
  （实测最小间距 **≥ 8 格 ≈ 256px**），避免一开局就贴脸；出生点周围会留出一小片空地，
  车头自动朝向地图中心。
- 墙体材质：约 **42% 是钢墙**（不可摧毁，反弹很硬）、**58% 是砖墙**（可以打穿）。
- 对局进行一段时间后开始**随机掉落特殊武器**，场地上最多同时存在 3 个（侧栏只显示图标，鼠标悬停看中文说明）：

  | 图标 | 名称 | 效果 |
  | --- | --- | --- |
  | ⚡ | 加速 | 移动速度 +45%，持续 18 秒 |
  | 🔥 | 连发 | 开火间隔缩短 58%，持续 18 秒 |
  | 🔱 | 三连发 | 一次射出 3 颗平行子弹，持续 18 秒 |
  | 🎯 | 穿甲弹 | 可击毁钢墙，子弹更快，持续 18 秒 |
  | 🔫 | 激光 | **下一次开火变成贯穿光束**，扫平沿途砖墙、钢墙**和草丛**，**只能用一次** |
  | 🛡 | 护盾 | **只挡 1 颗子弹**（挡完即失效），持续 14 秒 |
  | ❤️ | 加命 | 命数 +1（**最多 5 条**，满了就不再加） |
  | 👻 | 隐身 | **20 秒**隐形；**开火或捡到其他道具会立刻现形** |

  > **隐身只在联机模式掉落。** 单机和本地双人对战时对手就在同一块屏幕上（AI 也是直接读战场数据找目标），
  > 隐身没有意义，所以本地对局的道具池是 7 种、联机是 8 种。

- 场地上还有树丛（能藏住坦克）等元素，图形为纯几何图形组合，无贴图、无 3D、无光影。
  - **草丛变大了**：一丛草会盖住整格（连坦克一起遮住），但圆形叶团之间留着缝隙，看得出是一丛丛的草。
  - **草丛是"正常遮挡"**：草画在坦克上面，钻进去就被草盖住 —— 不是把人变没。
    躲进草丛时**不显示头顶名字**（名字会浮在草上方暴露位置）；**你自己**的车会另外半透明补画一层，
    免得连自己也看不见。草丛不挡子弹，子弹照常穿过去。
  - **子弹会把草打薄**：子弹每穿过一格草丛就削掉一档 —— 完整草丛 → **稀疏草丛**（又小又稀，**藏不住人**）→ 空地。
  - **激光是"大幅"清草**：激光扫过的草丛，正面那格直接烧成空地，周围一圈也一起被打薄/烧掉。
- **每局生命数可改**：房主在联机房间里可设 1~5 条（默认 1 条）；单机 / 本地双人也在开局面板里可选。
- **场上掉哪些道具，房主说了算**：联机房间里列出 8 种道具，**默认全选**，点一下即可取消/勾回
  （至少保留一种）。单机与本地双人不会掉「隐身」——同一块屏幕上看不见对手没有意义。
- **子弹不伤害自己（默认开启该保护）**：房间里有一开关「子弹会伤到自己」，默认**关闭**，
  也就是反弹回来的子弹不会再把自己打死；想恢复"会被自己打中"的硬核玩法就把它打开。
- **掉落节奏**：不再纯随机，而是「洗牌袋」——一轮之内 8 种各掉一次、顺序随机，
  刷新间隔 4~7 秒，约 40 秒就能把 8 种见一遍，不会再出现"玩一局连激光都没见到"。

### 2.2 三种模式

| 模式 | 说明 |
| --- | --- |
| **单人游戏** | 三档难度（简单 / 普通 / 困难）。AI 会持续增援，你只有 3 条命，比拼击杀数，成绩存本机。 |
| **多人游戏** | 同一台电脑双人对战。P1 用方向键，P2 用 `W A S D`。**局数制**，打完结算排名。 |
| **在线联机游戏** | **4 位房间号，支持 2~4 人**。房主新建房间 → 同学点「加入房间」输入房间号即可进入。 |

### 2.3 联机房间：准备制 + AI 开关

进入房间后，玩家列表里会实时显示每个人的状态：

| 玩家 | 显示 |
| --- | --- |
| 房主 | `房主 · 已就绪`（房主不需要点准备，他负责点开始） |
| 其他玩家 | `未准备` / `✔ 已准备`，各自有「我已准备好」按钮，可随时取消 |

- **只有所有人都准备了，房主的「开始游戏」按钮才会亮起**。
  条件不满足时按钮是灰的，并且**旁边会直接写出原因**，例如：
  「还有 1 人未准备：小明」「只有你 1 人：请打开「AI 坦克」开关，或等其他人加入」。
  能开始时显示绿色的「全员就绪，可以开始（共 2 人）」。
- **AI 坦克是可选开关，而且默认关闭**：房主可以在房间里打开「补充 AI 坦克」。
  - **关**（默认）：完全不加入任何 AI；此时如果房间里只有 1 个人，开始按钮会禁用并写明原因。
  - **开**：真人不足 2 人时自动补 1 辆 AI，一个人也能开局试玩。
  - 2 人及以上的真人对局，本来就不会加入任何 AI。
- 开赛时准备状态会自动清空，下一届回到大厅需要重新准备。
- **对局进行中有人退出，整场直接结束**：其余玩家会收到提示并回到主页，房间同时回收
  （不做"少一个人继续打"）。

### 2.4 局数与排名（房主可设）

- 房主在大厅设置 **对局局数**：**默认 20 局，最多 999 局**（1~999 之间任意值）。
- 每局重新随机地图；每局最后存活的坦克记 **1 胜**，击毁一辆坦克记 1 杀。
- **决出胜负后先等 2 秒再结算**：让最后一击的爆炸、碎片动画播完；
  这 2 秒里如果剩下的人也被打掉（同归于尽），本局就判 **平局（流局）**，双方都不记胜场。
- **胜利画面**：每局结束会在**正中间画出获胜的那辆坦克 + 玩家名**（同色的涂装、写着「本局胜者」），
  下面才是排名；并列流局则显示「平局」。
- **全部局数打完的结算界面**：中间是**总冠军**（画出坦克 + 名字 + 胜场/击杀），
  下面单独一行 **🎯 击杀榜第一**（击杀最多者，并列看死亡少），最后才是完整战绩排名。
- 单局时限 180 秒，超时按击杀数排名。
- **全部局数打完后结算总排名**：先比胜场 → 再比击杀 → 死亡少者靠前。
- 人数不足 2 人时，系统会自动补 AI 坦克，单人也能跑完所有局数。
- 其他操作：局间有结算面板与倒计时；对局中房主可随时在房内改颜色/涂装；打完可「回到大厅再来一局」。

### 2.5 房间内的自定义

进入房间后可以设置：

- **颜色**：8 种（蓝 / 红 / 绿 / 黄 / 紫 / 青 / 橙 / 白）
- **涂装**：4 种（经典 / 条纹 / 迷彩 / 霓虹）
- **键位**：上、下、左、右、开火共 5 个键，点按键框后按下新键即可改（Esc 取消），会做重复键校验

## 3. 五子棋

### 3.1 玩法

- 15×15 棋盘，传统规则：横、竖、斜任意方向**先连成五子或以上者获胜**。
- **每人只有一次悔棋机会，悔棋不需要对方同意**，点一下立即生效：
  - 只要**自己刚落下的那一手对方还没有应手**，就能直接撤回它，机会随即用掉；
  - 如果对方已经应手，这一手就不能再悔了 —— 机会**不会消耗**，等自己下一次落子后（对方还没应手时）再用；
  - 悔棋只撤回**最后落下的那一手**，撤回后轮次回到自己。
  - 单人对战电脑时同理，点「悔棋」撤回自己最近一手（连同电脑紧跟的应手），轮次回到你。
- **落子预览**：鼠标（或手指）在棋盘上选择落子位置时，会显示一颗半透明的预览棋子，颜色就是**当前该落子一方**的棋子颜色（黑方回合显黑子、白方回合显白子）；同一时刻**对方也能看到你在考虑的位置**（淡棋子 + 虚线圈）。
- 支持认输、重新开始、显示手数、显示坐标。

### 3.2 单人游戏

三档难度：简单（带随机性）/ 普通（会攻会守）/ 困难（额外做一步前瞻）。AI 基于棋型窗口评分，攻守兼备。

### 3.3 联机（邀请制）

- 每个人打开联机页都会看到一个 **本机专属邀请码**（由 IP 派生，6 位易读字符，同名机房内唯一；同一 IP 多开也会自动区分）。
- 想和谁下棋，就把自己的邀请码给他，或**输入对方的邀请码**点「发起邀请」。
- 对方会收到弹窗，**接受**后立即开局。
- **黑白轮换**：同一对玩家每再开一局，执黑/执白就互换一次（上一局执黑的这局执白），
  不会永远是同一个人先手。
- 对局结束后可以「邀他再来一局」（复用同一个邀请码）。

### 3.4 视觉风格

整页为**传统木质棋盘**风格：浅木色棋盘（#DEB887）配深棕线条与星位，棋子是纯黑与米白的圆形棋子，
最后一手用红点标记，连成五子画一条朴素的红棕细线。界面字体使用楷体 / 宋体等衬线字体，
按钮为木色圆角矩形，没有渐变发光、玻璃拟态、霓虹、粒子或 3D 效果，像把实体棋盘放在木桌上。

## 4. 设置（主页右上角「设置」）

- **昵称**：可以直接改，**改完立刻同步**到联机房间/棋盘（不用重进房间、不用刷新页面）。
- **音效音量**：0~100% 滑块 + 静音开关 + 试听。音效全部用 WebAudio 现场合成，**没有任何音频文件**。
- **键位设置**：玩家 1 / 玩家 2 各 5 个键，点一下再按新键即可修改，重复键会提示。
- 昵称同时用于单机记分与联机房间/棋盘显示；改完点保存即时生效。
- 设置保存在浏览器 localStorage，换电脑需要重新设置。

## 5. 目录结构

```
game/
├─ 启动游戏.bat               一键启动（双击，中文名最容易找）
├─ start.bat                  同上（英文名，供命令行/快捷方式使用）
├─ 开放防火墙端口.bat          别的电脑连不上时，右键「以管理员身份运行」放行端口
├─ package.json               无任何依赖，仅提供 npm start / npm test
├─ platform/                  ★ 平台层：与具体游戏无关的部分
│  ├─ server/
│  │  ├─ server.cjs           真正的入口：静态多根挂载 + 客户端注册 + IP 邀请码 + 60Hz 主循环 + 消息分发
│  │  ├─ server.js            防误点提示（被双击时给正常人话，Node 下会自动转发到 server.cjs）
│  │  └─ ws.js                自己实现的 WebSocket 服务端（RFC6455：握手/掩码/分片/ping-pong/close）
│  └─ web/
│     ├─ index.html           主页（**游戏卡片是脚本读 /api/status 渲染的**，新增游戏不用改这里）
│     └─ shared/              跨游戏通用库与样式
│        ├─ app.css           公共样式
│        ├─ core.js           设置存储、键位、WebAudio 音效、设置弹窗、Toast
│        └─ net.js            WebSocket 客户端（自动重连 / RTT 统计 / 消息分发）
├─ games/                     ★ 游戏层：一个游戏一个文件夹，改动互不影响
│  ├─ tank/                   坦克大战（自包含）
│  │  ├─ server/room.js       房间、局数制对局、服务端权威模拟、30Hz 状态广播
│  │  ├─ shared/tankcore.js   ★ 内核（浏览器与 Node 共用同一份代码）
```

### 为什么要分 platform / games

**平台层（`platform/`）**：只做「跑游戏」这件事 —— 静态资源、WebSocket、客户端注册、主循环，
**一行游戏规则都没有**。

**游戏层（`games/<名字>/`）**：每个游戏完全自包含，各占一个文件夹：

| 位置 | 作用 |
| --- | --- |
| `games/<名>/client/` | 该游戏的网页（HTML/CSS/JS） |
| `games/<名>/shared/` | 该游戏「浏览器 + Node 共用」的内核（只有需要时才建） |
| `games/<名>/server/room.js` | 该游戏的服务端逻辑 |

**隔离是怎么保证的**：

- **消息路由各写各的**：每个游戏的 `room.js` 用 `Hub.routes = { 'xxx.yyy': '方法名' }`
  自己声明能收哪些消息，主机启动时自动装配成路由表 —— 主机里**看不到任何 `tank.*` / `gomoku.*` 字样**。
- **静态资源按前缀挂载**：`games/tank/client/` 挂到 `/tank/`、`games/gomoku/client/` 挂到 `/gomoku/`，
  两个游戏的页面、样式、脚本互不引用。
- **自动发现**：主机扫描 `games/` 下带 `server/room.js` 的文件夹并挂载。
  **新增一个游戏 = 新建一个文件夹**，不用改平台层任何代码。
- **主页卡片也自动出现**：主页里只有一个空容器 `#hubGrid`，卡片是脚本按 `/api/status` 渲染的；
  标题、简介、标签、插画全部由游戏自己用 `Hub.title` / `Hub.card` 声明，
  平台层（`platform/`）里找不到任何一个游戏的名字。
- **撞车会被当面指出**：两个游戏注册了同一条消息类型时，主机保留先注册的那个，并在启动日志里打
  `[route conflict]`，同时写进 `/api/status` 的 `routeConflicts` —— 不再像以前那样无声地互相顶掉。
  共用同一个消息前缀、目录名撞上平台保留路径、卡片信息没声明，也都会以 `[game warn]` 列出来。
- **只有需要逐帧推进的游戏才实现 `step/broadcast`**（目前只有坦克），其余游戏主机不会去驱动。

> 想自己（或让 AI / 同学）加一个新游戏？看 **[`games/README.md`](games/README.md)** ——
> 里面有目录/接口约定、最小可运行模板，以及一段**可直接复制的提示词**。

### 联机为什么没延迟

- 该机房内的通信只有一跳：客户端 → 服务器 → 其他客户端，实测 RTT 约 **1ms**。
- 坦克采用**服务端权威模拟 + 客户端本地预测**：你的坦克按下键就动（本机立刻模拟），
  服务端 60Hz 模拟、30Hz 广播快照，客户端把权威位置平滑校正回来，因此「看到的即所按的」。
- 其他玩家与子弹做**快照插值**，画面平滑无抖动；快照体积约 250 字节，30Hz 下约 7.5 KB/s。
- 五子棋是回合制，无任何延迟问题。

```bash
node tools/platformtest.js                   # 平台：契约完整性、消息类型/前缀不撞车、自动发现没漏没多、卡片与主页
node tools/selftest.js                       # 内核：迷宫地图 / 旋转弹道 / 子弹反弹·寿命·自伤 / 子弹上限 / AI 对战 / 性能

node tools/uitest.js http://127.0.0.1:8080   # 界面：无头 Chrome 实测并输出截图到 tools/shots
npm test                                     # platformtest + selftest + nettest
```

> `platformtest.js` 会**自己拉起一个临时端口的服务端**，跑完自动关掉，所以在没有服务端在跑时也能单独执行；
> 也可以 `node tools/platformtest.js http://127.0.0.1:8080` 去测已经在跑的那个。

> 跑 `nettest.js` 前必须用下面两个环境变量启动服务器，**缺一不可**：
> - `WB_ROUND_LIMIT=6` —— 把单局时限压到 6 秒，否则「打满局数 → 总结算」那一段要等满 150 秒一局；
> - `WB_TEST_HOOKS=1` —— 打开 `tank.teleport` 这类只在测试环境生效的钩子。**少了它**，
>   「子弹穿过草丛把草打薄」那一组用例会因为坦克挪不到指定位置而失败（看着像玩法坏了，其实只是钩子没开）。
> ```bash
> set WB_ROUND_LIMIT=6 && set WB_TEST_HOOKS=1 && node platform/server/server.cjs --port 8080
> ```

> 职责划分：`ROUND_LIMIT`（tankcore 常量，默认 150 秒）是游戏真实单局时长，联机/本地/HUD 都读它，正式服运行时任何地方都不应改写它。
> `WB_ROUND_LIMIT`（环境变量）仅供自动化测试压缩服务端单局时限，不回写内核常量，测试值不会泄漏到正式服。

## 7. 常见问题

**Q：双击 `server\server.js` 弹窗报「语法错误 / 代码 800A03EA / Microsoft JScript 编译错误」？**
那是因为直接双击了 `.js` 文件 —— Windows 会用它自带的脚本宿主（JScript）去执行，
而 JScript 不认识现代 JS 语法（`const` 等），所以在第 5 行就报错了。**这不是游戏出错。**
正确做法：双击根目录的 **`启动游戏.bat`**，或在命令行执行 `node platform\server\server.cjs`。
（`server\server.js` 现在只是一个防误点提示文件，双击它只会弹出一句说明，不会再报错。）

**Q：双击 bat 窗口一闪就没了？**
说明没找到 Node.js。窗口里会提示下载地址；装好 Node 后重新双击即可。
如果确认装了但仍然找不到，可能是安装时没勾选「加入 PATH」，脚本会自动去
`C:\Program Files\nodejs\node.exe` 等常见位置再找一遍。

**Q：其他电脑打不开页面？**
检查三点：① 是否在同一局域网；② Windows 防火墙是否放行（首次启动要选「允许访问」）；
③ 地址是否用了服务器的局域网 IP 而非 `localhost`（启动时控制台会打印可用的局域网地址）。

**Q：房间号输错了？**
会提示「房间号不存在」，重新输入即可。房间号是每次新建房间随机分配的 4 位数。

**Q：五子棋邀请时说「对方已离线」？**
邀请码对应的是**当前在线连接**，对方关掉页面或换电脑后邀请码会变，需要重新让他报一次邀请码。

**Q：五子棋「悔棋」按钮点不动？**
悔棋只在**自己刚下完、对方还没应手**的那一小段时间内可用（按钮会实时点亮，侧栏也会提示「现在可以悔棋」）。
对方一旦应手，这一手就不能悔了；机会不会浪费，等你下一次落子后再悔即可。每人一共只有 1 次机会。

**Q：对局中途关掉网页会怎样？**
坦克对局中离开会立即判负（剩余玩家继续打完剩余局数）；五子棋会通知对手「对方已掉线」。服务器会自动回收房间与对局，不会残留。

**Q：能不能改地图大小 / 单局时限 / 生命数？**
地图大小与单局时限在 `games/tank/shared/tankcore.js` 顶部的常量里（`TILE`、`ROUND_LIMIT`、`RESPAWN_DELAY` 等），
服务端与客户端共用这份文件，改一处即可全局生效。
**生命数不用改代码**：联机房主在房间里直接选 1~5 条（默认 1 条），单机 / 本地双人在开局面板上选。

**Q：想改服务器端口？**
`node platform/server/server.cjs --port 9000`，或设环境变量 `PORT=9000`。

```bash
git clone https://github.com/WannaBeCute/lan-games.git
cd lan-games
node platform/server/server.cjs        # 起服务端，浏览器打开 http://127.0.0.1:8080
```

想加一个新游戏：在 `games/` 下新建一个文件夹（里面有 `server/room.js`）就行，
`platform/` 一行都不用改 —— 服务端会自动发现并装配、主页会自动多出一张卡片。
契约、卡片声明（`Hub.title` / `Hub.order` / `Hub.card`）、最小模板，
以及一段可直接发给同学或 AI 的提示词，都在 [`games/README.md`](games/README.md)。

**提交改动前请跑一遍自检**（动了内核或服务端逻辑的尤其要跑）：

```bash
node tools/platformtest.js                      # 平台装配：契约、消息类型/前缀不撞车、卡片与主页
node tools/selftest.js                          # 内核：地图、弹道、子弹反弹/寿命/自伤、AI、性能

node tools/uitest.js http://127.0.0.1:8080      # 界面（无头 Chrome）
```

**协作流程**：从 `master` 开一个描述性分支（例如 `feat/snake`）→ 改完跑通自检 → 提 PR，
在说明里写清改了什么、跑了哪些测试。**一个游戏只动 `games/<名字>/` 里的文件**；
确实需要改 `platform/`（比如动服务端通用能力）时，先开个 Issue 说一声，免得和别人的改动撞车。

> 项目有几条硬约定：**服务端零 npm 依赖**（只用 Node 内置模块）、**前端不用构建工具**
> （传统 `<script>` + 全局命名空间）、**游戏之间必须隔离**（平台层不出现任何具体游戏的名字）。
> 动手前先看 **5. 目录结构** 和 `games/README.md` 里的约定表。
